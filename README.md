# STM32 / FreeRTOS / SPI: асинхронный обмен данными

## Задача

Требуется организовать для STM32 под управлением FreeRTOS асинхронный обмен данными между двумя потоками по одному SPI-интерфейсу с использованием HAL:

- два разных блока данных одинакового размера, порядка 10 КБ;
- CRC16 для каждого блока;
- передача блоками по 64 байта;
- период запросов Master — 200 мс (5 Гц);
- период запросов Slave — 333 мс (примерно 3 Гц);
- после получения выполняется повторный CRC16 и сравнение с CRC, переданным в DONE-кадре.

## Архитектура

Проект разделён на три части:

1. `App/` — логика обмена, протокол, CRC, буферы, планировщик и FreeRTOS-задачи.
2. `Core/` — точка интеграции с проектом STM32CubeMX/HAL.
3. `HostSim/` — симулятор для проверки протокола и обмена без физической платы.

### Роли Master и Slave

Один экземпляр прошивки работает в одной роли: Master или Slave. Роль, идентификатор блока и начальное значение данных задаются при вызове `app_start()`.

На каждой плате должен быть свой экземпляр прошивки с соответствующей ролью. В `Core/Src/main.c` эти параметры вынесены в отдельные макросы `APP_ROLE`, `APP_BLOB_ID`, `APP_SEED` и `APP_EXPECTED_BLOB_ID`.

### Владение SPI

Несколько FreeRTOS-задач не должны одновременно обращаться к одному SPI handle. Поэтому планировщик только помещает запрос в очередь, а `spi_owner_task` последовательно выполняет операции с SPI.

### Асинхронная передача

На STM32 используется `HAL_SPI_TransmitReceive_DMA()`. После завершения DMA HAL вызывает callback, который передаёт событие через бинарный семафор FreeRTOS и позволяет задаче продолжить выполнение.

### Протокол

Каждая SPI-транзакция использует фиксированный кадр размером 74 байта:

| Поле | Размер |
|---|---:|
| SOF | 1 |
| Version | 1 |
| Type | 1 |
| Blob ID | 1 |
| Sequence | 2 |
| Payload length | 1 |
| Reserved | 1 |
| Payload | 64 |
| Frame CRC16 | 2 |

Итого: 74 байта, из них 64 байта — полезная нагрузка.

CRC кадра рассчитывается по заголовку и payload. Дополнительно для каждого блока данных рассчитывается CRC16 всего блока размером 10 КБ. После завершения передачи получатель сравнивает полученный CRC с CRC из DONE-кадра.

## Тайминги

Планировщик Master формирует запрос каждые 200 мс, то есть 5 раз в секунду.

Планировщик Slave формирует запрос каждые 333 мс, то есть примерно 3 раза в секунду.

В обычном SPI тактовый сигнал формирует Master. Поэтому для физической передачи со стороны Slave требуется конкретная схема взаимодействия с Master: например, отдельный сигнал запроса, NSS или другой механизм арбитража. В условии не заданы модель STM32, распиновка и такой механизм, поэтому в проекте фиксируются требуемые периоды планировщиков, а способ физического запуска SPI на конкретной плате задаётся при интеграции.

## Сборка и запуск Host Simulator

Из корня проекта:

```bash
cmake -S . -B build
cmake --build build
./build/HostSim/spi_test_sim
```

Ожидаемый результат:

```text
MASTER: blob CRC = ...
SLAVE : blob CRC = ...
MASTER: received CRC = ...
SLAVE : received CRC = ...
Frames master->slave: 161
Frames slave->master: 161
RESULT: PASS
```

## Что проверяет Host Simulator

- CRC16-CCITT на контрольном значении;
- размер каждого блока — 10 КБ;
- разные исходные данные Master и Slave;
- CRC16 каждого блока;
- передачу по 64 байта;
- последовательности `0..159` для DATA и `160` для DONE;
- восстановление блока без изменения данных;
- CRC восстановленного блока;
- соответствие количества кадров ожидаемому значению;
- обнаружение повреждения payload;
- обнаружение повреждения заголовка.

Периоды планировщиков 5 Гц и 3 Гц относятся к FreeRTOS-части и в Host Simulator не моделируются по времени.

## Интеграция со STM32

Для подключения к конкретной плате необходимо:

1. создать проект в STM32CubeMX;
2. включить FreeRTOS и SPI;
3. включить DMA для TX/RX;
4. настроить GPIO, NSS и остальные параметры SPI;
5. настроить требуемую схему взаимодействия Master и Slave;
6. сгенерировать проект;
7. добавить `App/Inc` и `App/Src`;
8. задать роль и параметры блока в `Core/Src/main.c`;
9. вызвать `app_start(&hspi1, APP_ROLE, APP_BLOB_ID, APP_SEED, APP_EXPECTED_BLOB_ID)` после инициализации HAL и SPI.

`Core/Src/main.c` содержит точку запуска и места для кода инициализации, который генерируется STM32CubeMX.
