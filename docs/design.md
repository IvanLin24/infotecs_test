# Заметки по проектированию

## 1. Данные

Каждый экземпляр прошивки хранит свой исходный блок размером 10 КБ.

10 КБ / 64 байта = 160 DATA-кадров.

Итоговый CRC рассчитывается по восстановленному блоку размером 10 КБ, а не по отдельным кадрам.

## 2. Роли Master и Slave

Один экземпляр прошивки работает в одной роли: Master или Slave. Параметры роли и блока передаются в `app_start()`.

Два устройства используют один и тот же код обмена, но с разными ролями, идентификаторами блоков и начальными значениями данных.

## 3. Формат кадра

Каждая SPI-транзакция передаёт кадр размером 74 байта:

- 1 байт — признак начала кадра;
- 1 байт — версия протокола;
- 1 байт — тип кадра;
- 1 байт — идентификатор блока;
- 2 байта — номер последовательности;
- 1 байт — длина полезной части;
- 1 байт — резерв;
- 64 байта — полезная часть;
- 2 байта — CRC16 кадра.

Для DATA полезная часть всегда содержит 64 байта данных. DONE содержит CRC16 всего переданного блока в первых двух байтах полезной части.

## 4. Целостность

CRC кадра позволяет обнаружить повреждение заголовка или полезной части.

CRC всего блока дополнительно подтверждает, что все 160 принятых кадров собраны в исходный буфер без изменений.

При получении DATA проверяются формат кадра, идентификатор блока и ожидаемый номер последовательности. После DONE повторно рассчитывается CRC восстановленного блока и сравнивается с переданным значением.

## 5. Конкурентный доступ

Планировщик не обращается к HAL напрямую. Он помещает запрос на передачу в очередь.

Только `spi_owner_task` работает с SPI handle.

Завершение DMA из ISR callback преобразуется в бинарный семафор FreeRTOS, после чего задача продолжает выполнение.

Такой подход исключает одновременный доступ нескольких задач к состоянию SPI HAL.

## 6. Тайминги

Период планировщика Master — 200 мс, то есть 5 Гц.

Период планировщика Slave — 333 мс, то есть примерно 3 Гц.

В обычном SPI тактирование формирует Master. Поэтому эти значения определяют период формирования запросов планировщиками. Физический запуск SPI-транзакции со стороны Slave требует механизма синхронизации с Master, который в условии не задан. Его настройка относится к интеграции с конкретной платой и схемой.

## 7. Проверка на ПК

Host Simulator не моделирует работу FreeRTOS и физический SPI. Он проверяет протокол и логику обмена без платы:

- CRC16-CCITT на контрольном значении;
- передачу обоих блоков;
- 160 DATA-кадров и один DONE-кадр для каждого направления;
- восстановление данных;
- итоговый CRC;
- обнаружение повреждения payload и заголовка.
